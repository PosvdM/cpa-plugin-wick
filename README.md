# Wick

[English](./README_EN.md)

Wick（挑灯）是 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)（CPA）的原生插件。Claude Code 经 CPA 使用 Claude 订阅账号时，Wick 在对话空闲期间定时读取一次 5 分钟提示缓存，回到对话时仍能命中原来的缓存。每一次读取称为“挑灯”：灯火将弱时挑一下灯芯，灯就继续亮着。

## 用途

Claude 的提示缓存有两种有效期：5 分钟的写入价是输入价的 1.25 倍，1 小时的是 2 倍；读取缓存只需 0.1 倍。每次读取都会让缓存重新计时。原生 Claude Code 默认使用 5 分钟缓存，离开超过 5 分钟后，下一条消息要按 1.25 倍重新写入整个上下文。上下文有几十万 token 时，这一次重写会消耗明显的额度。

Wick 让平时的写入继续按 5 分钟的价格计算，同时在对话空闲时每隔 4 分 20 秒到 4 分 50 秒挑灯一次。默认最多连续挑灯 6 次，缓存可保持约 30 分钟。默认时长可在[管理页面](#管理页面)中选择；临时离开较久时，也可以为单个对话另设 1 到 24 小时。

## 工作方式

- Wick 记录每个对话的最后一个请求。从这个请求开始计时，在 `interval_min` 到 `interval_max` 秒之间随机选一个时刻，把这个请求原样再发一次，收到第一个事件 `message_start` 后立即断开，相当于发出请求后马上按 Esc。收到 `message_start` 时缓存已经读完，有效期随之重新计算。断开前上游可能已生成几个 token。结果不会回到 Claude Code，对话的上下文保持不变。
- 挑灯请求经过 CPA 的模型执行器，使用原请求的账号和请求头，因此与原请求命中同一份缓存。
- 对话中出现新请求时，计时从新请求开始，挑灯次数清零，单独设置的时长恢复为默认时长。
- 以下情况熄灭，即停止挑灯：达到 `max_pings` 次，或到达单独设置的时长；挑灯请求失败；挑灯请求写入了缓存（说明缓存已过期或请求不一致，再挑灯也无法命中）；原请求失败；插件被关闭。按 Esc 中断的请求继续挑灯。
- 只处理原生 Claude Code 的流式请求。以下请求不挑灯：使用 1 小时缓存的请求；请求体小于 `min_body_kb` 的请求，如生成标题等辅助请求。
- 同一会话中，主对话和每个 subagent 分别挑灯。主对话收到下一个请求时，在它等待期间开始的 subagent 视为已结束，随之熄灭。
- 正在挑灯的对话保存在[数据目录](#数据目录)中。CPA 重启或插件重新加载后，缓存尚未过期的对话按原来的计划继续挑灯，已挑灯的次数和单独设置的时长保持不变；缓存已经过期的对话不再恢复。

挑灯的读取量会计入订阅额度。每次挑灯读取整个上下文，按 0.1 倍计价；如果离开的时间短于一两次挑灯的间隔，节省的额度较少。

## 要求

- CPA v8.0.39 或更新版本，并开启插件（`plugins.enabled: true`）。
- 原生 Claude Code 经 CPA 使用 Claude 订阅账号。其他客户端（pi、Cherry Studio 等）的请求不处理。

## 安装

1. 在 [Releases](https://github.com/PosvdM/cpa-plugin-wick/releases) 下载与 CPA 所在系统对应的 zip，或按 [架构文档](./docs/architecture.md#构建) 自行构建。
2. 把动态库（Linux 为 `wick-v<版本>.so`）放进 CPA 插件目录下的 `<系统>/<架构>/` 子目录，例如 `plugins/linux/arm64/`。Docker 部署时，插件目录是挂载到容器 `/CLIProxyAPI/plugins` 的宿主机目录。
3. 在 CPA 的 `config.yaml` 中启用插件：

   ```yaml
   plugins:
     enabled: true
     configs:
       wick:
         enabled: true
   ```

CPA 检测到配置变化后加载插件，不需要重启。

## 配置

配置写在 `config.yaml` 的 `plugins.configs.wick` 下，修改后自动生效，也可以在[管理页面](#管理页面)中修改。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `interval_min` | `260` | 最短挑灯间隔（秒） |
| `interval_max` | `290` | 最长挑灯间隔（秒），不超过 `299` |
| `max_pings` | `6` | 一次空闲最多挑灯几次；`0` 关闭挑灯 |
| `min_body_kb` | `64` | 请求体小于此大小（KiB）时不挑灯 |
| `history_retention_days` | `40` | 挑灯记录保留的天数，`1` 到 `3650` |
| `data_dir` | 空 | 数据目录。为空时使用 `<plugins.dir>/data/wick`；相对路径相对于 CPA 的工作目录 |

对话空闲后，缓存约保持 `max_pings` × 平均间隔 + 5 分钟，默认设置下约 32 分钟。缓存的有效期从 Anthropic 收到请求时开始计算，网络延迟也计入其中，因此 `interval_max` 应与 300 秒留出余量。配置无效时插件使用默认值，并在 CPA 日志中写一条警告。

## 管理页面

在 CPA 管理中心的插件菜单中打开 **Wick**。页面使用管理中心登录时记住的管理密钥，没有时请在页面中输入；主题和语言跟随管理中心。

- **设置**：**默认挑灯时长**可选“关闭”“15 分钟”“30 分钟”“1 小时”或“自定义”，分别把 `max_pings` 设为 `0`、`2`、`6`、`12` 或填写的次数，下方显示按当前间隔估算的缓存保持时间。**高级设置**对所有对话生效，可修改 `interval_min`、`interval_max`、`min_body_kb` 和 `history_retention_days`。修改后自动保存到 `config.yaml`，插件几秒内应用。
- **正在挑灯的对话**：每个对话显示客户端（Claude Code、Claude Desktop、VS Code 等，取自请求的 User-Agent）和第一句话，subagent 标有“子代理”；悬停时显示完整的第一句话、项目目录和会话 ID。另有模型和账号、上次挑灯读取的缓存 token 数、已挑灯次数、空闲时长和下次挑灯的倒计时。**时长**可选“默认”、1、2、4、8 小时或自定义小时数，从设置时起算，下方显示挑灯到何时。**熄灭**停止该对话的挑灯，直到它收到下一个请求。
- **挑灯记录**：可切换 24 小时、7 天和全部，显示所选范围内的累计次数、失败次数、读取和写入的缓存 token 数，以及每次挑灯的时间、对话、缓存 token 数和结果。列表先显示 20 条，可继续展开。

页面上的第一句话是对话中第一条用户消息里用户输入的文字，Claude Code 注入的系统提醒和本地命令输出不计在内；以斜杠命令开始的对话显示命令名和参数。

## 数据目录

数据目录默认为 `<plugins.dir>/data/wick`，Docker 部署时位于挂载的插件目录中。文件权限为 `0600`，只有运行 CPA 的用户可以读取。

| 路径 | 内容 |
| --- | --- |
| `history/<UTC 日期>.jsonl` | 挑灯记录，每次挑灯一行：时间、会话 ID 和对话键的前 8 位、模型、客户端、项目目录、第一句话的前 80 个字、缓存 token 数和结果。超过 `history_retention_days` 天的文件自动删除 |
| `conversations/` | 正在挑灯的对话：每个对话的最后一个请求和挑灯计划。对话熄灭后删除对应文件 |

## 日志和接口

每次挑灯在 CPA 日志中写一条记录，包括会话 ID 的前 8 位、模型、第几次挑灯，以及读取和写入的缓存 token 数，例如：

```text
wick: ping session=1a2b3c4d key=5e6f7a8b ping=3 cache_read=322200 cache_creation=0 input=3 output=1 model=claude-opus-5-5
```

`output` 是 `message_start` 中的数字，不含断开前生成的 token。

管理页面使用的接口也可以直接调用，都需要 CPA 管理密钥。`GET /v0/management/wick/status` 返回正在挑灯的对话，`GET /v0/management/wick/history` 返回挑灯记录，参数见[架构文档](./docs/architecture.md#管理接口和页面)：

```bash
curl -H "Authorization: Bearer <管理密钥>" http://127.0.0.1:8317/v0/management/wick/status
```

## 安全与风险

- 正在挑灯的对话的最后一个请求包含整段对话内容，保存在内存和数据目录的 `conversations/` 中，对话熄灭后删除；挑灯记录中保存第一句话的前 80 个字。请求头中客户端访问 CPA 用的密钥（`Authorization`、`X-Api-Key`）不保存。对话内容不写入日志。
- 挑灯请求与原请求完全相同，并且间隔随机，但长时间按规律重发同一请求并中断，仍可能被服务方识别。通过 CPA 使用订阅账号本身也有账号风险，请自行判断。
- 挑灯请求失败（如限流）时，CPA 会像处理普通请求一样让账号进入冷却，冷却期间你的下一个请求也会被拒绝。
